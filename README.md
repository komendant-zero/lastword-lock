# 🔒 LastWord Lock (`lastword-lock`)

**LastWord Lock** — это CLI-приложение на Python для шифрования файлов, расшифровка которых требует процесса доказательства работы (**Proof-of-Work / майнинга**).

Главная особенность: **расшифровкой может заниматься буквально любое устройство** — от мощного сервера и ноутбука до смартфона (iPhone / Android) или планшета через встроенный браузерный Web Miner без необходимости устанавливать Python или стороннее ПО.

---

## ⚡ Принцип работы

1. **Мгновенное шифрование ($O(1)$)**:
   - Файл шифруется симметричным шифром **AES-256-GCM** со случайным 256-битным ключом $K_{file}$.
   - Создается криптографическая PoW-задача: генерируется секретный нонс $S \in [0, 2^D)$ (где $D$ — битовая сложность) и соль $Salt$.
   - Вычисляется целевой хеш $H_{target} = \text{SHA-256}(Salt \parallel S)$.
   - Мастер-ключ формируется через HKDF: $K_{master} = \text{HKDF-SHA256}(S, Salt)$. Ключ $K_{file}$ шифруется с помощью $K_{master}$.
   - Шифрование происходит **мгновенно** (доли секунды даже для больших файлов).

2. **Майнинг для расшифровки**:
   - Чтобы расшифровать файл, нужно найти нонс $X \in [0, 2^D)$, для которого $\text{SHA-256}(Salt \parallel X) == H_{target}$.
   - В пространстве $[0, 2^D)$ существует **ровно одно решение**.
   - Среднее число операций хеширования для нахождения ключа — $2^{D-1}$.

3. **Распределенный пул и любое устройство**:
   - Координатор делит диапазон $[0, 2^D)$ на независимые непересекающиеся блоки (chunks).
   - Любое устройство запрашивает блок, проверяет нонсы и отправляет результат.
   - Как только **хотя бы одно устройство** находит решение, файл мгновенно расшифровывается, а веб-страница предлагает скачать готовый файл!

## 🚀 Установка

Требуется **Python 3.9+**.

```bash
git clone https://github.com/komendant-zero/lastword-lock.git
cd lastword-lock

# Установка зависимостей и CLI
pip install -e .
```

После установки доступна глобальная консольная команда `lastword-lock`.

## 🛠 Быстрый старт и команды

```
Usage: lastword-lock [OPTIONS] COMMAND [ARGS]...

Commands:
  encrypt    Зашифровать файл с PoW-головоломкой
  decrypt    Локальная расшифровка (майнинг на всех ядрах CPU)
  pool       Запуск сервера майнинг-пула (веб-интерфейс + QR-код)
  worker     Подключение CLI-воркера к удаленному пулу
  inspect    Просмотр метаданных и сложности .lwl контейнера
  benchmark  Тест скорости хеширования и калькулятор сложности
```

### 1. Тестирование скорости оборудования (`benchmark`)
Замеряет хешрейт вашего процессора (1 ядро и все ядра) и выводит таблицу расчетного времени подбора:
```bash
lastword-lock benchmark
```

---

### 2. Шифрование файла (`encrypt`)
Сложность майнинга можно задавать тремя способами:
1. **Готовыми пресетами** `-p` (`test`, `demo`, `quick`, `normal`, `hard`, `extreme`, `paranoid`).
2. **Желаемым временем майнинга** `-t` (`30s`, `5m`, `30m`, `2h`, `1d`), которое автоматически калибруется под хешрейт вашего ПК.
3. **Точной битовой сложностью** `-d` (например, 28, 30, 32, 34, 36 бит).

> **По умолчанию** (без флагов) используется пресет `normal` (29 бит ~ 536 млн нонсов, что занимает ~1-4 минуты).

```bash
# По умолчанию: сложность 29 бит (~536 млн нонсов, ~2-4 минуты)
lastword-lock encrypt document.pdf

# Использование пресетов:
lastword-lock encrypt document.pdf -p hard      # 32 бита (~4.3 млрд нонсов, ~20-40 минут)
lastword-lock encrypt document.pdf -p extreme   # 35 бит (~34 млрд нонсов, ~2-4 часа)
lastword-lock encrypt document.pdf -p paranoid  # 38 бит (~275 млрд нонсов, ~1-2 суток)

# Точная калибровка под желаемое время майнинга:
lastword-lock encrypt report.docx -t 30m -o report.lwl   # Под 30 минут
lastword-lock encrypt archive.zip -t 2h -o archive.lwl   # Под 2 часа

# Прямое указание битовой сложности:
lastword-lock encrypt database.sql -d 34        # 34 бита (~17.2 млрд нонсов)

# С удалением исходного незашифрованного файла:
lastword-lock encrypt secret.txt -p hard --delete-original
```

---

### 3. Расшифровка на одном компьютере (`decrypt`)
Многопроцессный майнинг с красивым прогресс-баром Rich, отображением хешрейта, времени и оставшихся попыток:

```bash
# Майнинг на всех доступных ядрах процессора
lastword-lock decrypt locked.lwl -o document.pdf

# Ограничение числа потоков (например, 4 ядра)
lastword-lock decrypt locked.lwl -t 4
```

---

### 4. Распределенный майнинг-пул (`pool`) и режим конкурса (`--contest`)
Запускает координатор пула, печатает в консоль **ASCII QR-код** и открывает доступ к футуристичному веб-майнеру:

```bash
# Обычный кооперативный пул (результат доступен всем):
lastword pool locked.lwl --port 8080

# Режим конкурса с призом (--contest):
# Только тот воркер/устройство, которое первым нашло нонс, получает криптографический claim-token
# и может скачать расшифрованный файл! Личеры и опоздавшие не смогут забрать приз.
lastword pool locked.lwl --port 8080 --contest
```

Что происходит при запуске:
- В терминале отображается локальный сетевой адрес (например, `http://192.168.1.50:8080`) и **QR-код**.
- **Любой смартфон** (iPhone, Android) или планшет в той же Wi-Fi сети может просто **навести камеру на QR-код** и открыть страницу в браузере.
- В браузере запускаются высокопроизводительные **Web Workers** с оптимизированным 32-битным SHA-256 (до 2.7 MH/s на ядро без установки какого-либо ПО!).
- Любой другой ПК или сервер в сети может присоединиться через консоль:
  ```bash
  lastword worker http://192.168.1.50:8080 --name "Linux-Server" --threads 16
  ```
- В режиме конкурса (`--contest`) CLI-воркер победителя **автоматически скачивает и сохраняет** приз на диск локально (`claimed_<filename>`).

---

### 5. CLI-воркер (`worker`)
Подключается к запущенному пулу по сети и вычисляет выделенные координатором диапазоны нонсов:

```bash
lastword worker http://192.168.1.50:8080 --name "Worker-Ryzen" --threads 8
```

### 6. Защита от видеокарт (Memory-Hard Scrypt) и реальность GPU vs CPU

При обычном SHA-256 видеокарты (GPU) перебирают хеши в десятки тысяч раз быстрее процессоров (одна RTX 4090 выдает ~20 GH/s против ~2-4 MH/s на многоядерном CPU).
Для сокращения преимущества GPU используйте режим **`--algo scrypt`**:
```bash
# Памятезатратный майнинг (16 МБ RAM на попытку):
lastword encrypt wallet.dat --algo scrypt -p normal
```
Каждая попытка требует ~16 МБ оперативной памяти ($N=16384, r=8, p=1$), упираясь в пропускную способность видеопамяти.

> [!IMPORTANT]
> **Честность между участниками в конкурсах:**
> - Scrypt сжимает преимущество GPU с ~10,000× до **оценочно ~100×** (~25 KH/s на топовой GPU против ~200 H/s на CPU). Цифра 25 KH/s рассчитана исходя из пропускной способности VRAM.
> - **В любом параллельном Proof-of-Work (и SHA-256, и Scrypt) при открытом соревновании побеждает владелец мощного GPU.** Пресет `paranoid` на Scrypt решается на GPU за считанные минуты.
> - Любая параллельная сложность оказывается либо «GPU решит мгновенно», либо «CPU не дойдёт никогда».
> - Если организатору необходима абсолютная математическая честность между слабыми и сильными устройствами, требуется **последовательная** задача (Time-Lock Puzzles RSW-96 / Sloth VDF), которую физически нельзя ускорить параллельными ядрами. Пул `lastword` предназначен для распределенной кооперации или конкурсов в контролируемых средах.

### 7. Правила проведения конкурсов (`--contest`)

> [!WARNING]
> **1. НИКОГДА не выкладывайте файл `.lwl` в открытый доступ!**
> Для участия в пуле файл `.lwl` участникам **не нужен** — сервер пула отдаёт `salt` и `target_hash` через `/api/info`. Если выложить файл `.lwl` в публичный доступ, любой участник сможет скачать его и замайнить локально на ферме GPU в обход пула, полностью обесценив защиту режима конкурса.

> [!TIP]
> **2. Защита от перехвата в сети (HTTPS и Commit-Reveal):**
> - Для защиты от перехвата решения в открытых сетях (Wi-Fi, провайдер, прокси) воркеры используют схему **Commit-Reveal**: сначала на `/api/commit` отправляется криптографический хэш `sha256(nonce || worker_id)`. Пул фиксирует точное время коммита. Только после подтверждения коммита отправляется сам нонс. Даже перехватив нонс в открытом трафике, злоумышленник не сможет заявить победу со своим `worker_id`, так как время его коммита будет позже.
> - При проведении публичных конкурсов через интернет сервер координатора следует запускать за reverse proxy с HTTPS (Caddy, Nginx или Cloudflare Tunnel).

## 🔒 Безопасность и архитектура

- **Защита от Path Traversal**: При распаковке имя файла строго санитизируется (`Path.name`), исключая уязвимости с записью в системные каталоги (`../../.bashrc`).
- **Аутентификация заголовка (AES-GCM AAD)**: Заголовок контейнера включен в *Associated Authenticated Data*. Любая попытка изменить хотя бы один байт в заголовке приводит к немедленной ошибке `InvalidTag` при расшифровке.
- **Безопасность недоверенных файлов `.lwl`**:
  - Строгий лимит на размер заголовка: не более 64 КБ (`MAX_HEADER_SIZE`). Файлы с поддельными заголовками в гигабайты не смогут вызвать отказ в обслуживании (OOM).
  - Валидация сложности (от 1 до 62 бит), неотрицательного размера файла и фиксированных длин криптографических параметров. Размер пространства поиска (`search_space`) всегда пересчитывается пулом самостоятельно, а не берется на веру из файла.
- **Commit-Reveal и защита от саботажа в пуле**:
  - Воркер подтверждает владение диапазоном (`lease.worker_id == worker_id`), исключая саботаж чужих лизов через `/api/progress`.
  - При обнаружении ложных отчетов пул запускает повторный проход со сбросом счетчиков прогресса, отдавая диапазоны другим воркерам (диапазон не переназначается тому же воркеру, который рапортовал о нем).
  - Асинхронный event loop координатора защищен: тяжелая проверка Scrypt и расшифровка вынесены в пул потоков (`run_in_threadpool`), а эндпоинт `/api/submit` защищен от спама лимитом запросов.
- **Автономность**: Все веб-ассеты (CSS, JS, логика Web Worker) встроены в проект и не требуют внешних CDN — всё работает даже в изолированной локальной сети без интернета.
