# 🔒 LastWord Lock (`lastword-lock`)

**LastWord Lock** — криптографическая утилита и движок безвозвратного криптографического уничтожения данных (**Crypto-Shredder / Digital Black Hole**).

Проект трансформирует любой файл в необратимый криптографический белый шум, который **математически невозможно расшифровать никакими способами** ни автору, ни спецслужбам, ни квантовым компьютерам или суперкомпьютерам будущего.

---

## ⚡ Архитектура и принцип невозможности расшифровки

1. **512-битный каскад двух независимых шифров (AEAD Cascade)**:
   - Генерируются 512 бит истинной криптографической энтропии от аппаратного генератора ОС (`secrets.token_bytes(64)`).
   - Энтропия расщепляется на два независимых 256-битных мастер-ключа:
     - **Слой 1**: 256-битный потоковый шифр **ChaCha20-Poly1305** с уникальным 96-битным одноразовым числом (nonce).
     - **Слой 2**: 256-битный блочный шифр **AES-256-GCM** с независимым 96-битным IV и привязкой заголовка через AAD (*Associated Authenticated Data*).
   - Двойное шифрование гарантирует: даже если в будущем будет обнаружена теоретическая уязвимость в AES или ChaCha20, второй независимый слой сохраняет абсолютную стойкость.

2. **Аппаратное затирание ключей в оперативной памяти (RAM Zeroization)**:
   - Ключевые буферы размещаются в изменяемых областях памяти (`bytearray`).
   - Сразу после шифрования блок `finally` вызывает функцию безопасного затирания через вызов Си-уровня `ctypes.memset`, заполняя все области памяти нулями (`0x00`).
   - Ключи **никогда не сохраняются на диск, не выводятся в терминал и не передаются по сети**.

3. **Многопроходное криминалистическое стирание с диска (DoD 5220.22-M + `fsync`)**:
   - При шифровании исходный незашифрованный файл на физическом накопителе подвергается 3-проходному перезаписыванию:
     - **Проход 1**: Запись случайного шума (`os.urandom`) + `os.fsync`.
     - **Проход 2**: Запись инвертированного битового паттерна (`0xAA`) + `os.fsync`.
     - **Проход 3**: Запись нулей (`0x00`) + `os.fsync`.
   - Вызов `os.fsync` после каждого прохода принудительно сбрасывает кэш контроллера накопителя, гарантируя физическую перезапись магнитных или полупроводниковых ячеек перед удалением файла.

4. **Криптографический сертификат уничтожения (Certificate of Destruction)**:
   - До уничтожения вычисляется контрольная сумма SHA-256 исходного содержимого.
   - Она сохраняется в заголовке контейнера `.lwl` как математическое доказательство того, какой именно документ был уничтожен, не раскрывая его содержимого.
   - Вероятность восстановления ключа перебором составляет $2^{-512}$ (абсолютный ноль в законах физики Вселенной).

## 🚀 Установка

Требуется **Python 3.9+**.

```bash
git clone https://github.com/komendant-zero/lastword-lock.git
cd lastword-lock

# Установка зависимостей и CLI
pip install -e .
```

После установки доступна глобальная консольная команда `lastword-lock` (или короткий алиас `lastword`).

## 🛠 Команды

```
Usage: lastword-lock [OPTIONS] COMMAND [ARGS]...

Commands:
  encrypt      Безвозвратно уничтожить файл (Crypto-Shredder / Черная дыра)

  inspect      Просмотр сертификата уничтожения и метаданных .lwl
  server       Запуск локального веб-приложения с QR-кодом для смартфонов

  benchmark    Тест скорости каскадного шифрования (MB/s)
  pool         Запуск координатора с веб-интерфейсом
  worker       Подключение воркера к координатору
```

### 1. Безвозвратное криптографическое уничтожение (`encrypt`)

Превращает файл в чистый математический белый шум, стирает ключи из RAM и перезаписывает физические секторы диска:

```bash
# По умолчанию: уничтожение файла и 3-проходное стирание оригинала на диске
lastword-lock encrypt classified_report.pdf

# Сохранить исходный файл без стирания с диска (только создать зашифрованную черную дыру):
lastword-lock encrypt document.docx --no-wipe-source -o document.docx.lwl
```

В консоль выводится защищённый **Сертификат безвозвратного криптографического уничтожения**:
```
┌───────── 🔒 CERTIFICATE OF IRREVERSIBLE CRYPTOGRAPHIC DESTRUCTION ──────────┐
│ Target File:                    classified_report.pdf                       │
│ Original Size:                  1.42 MB                                     │
│ Content Fingerprint (SHA-256):  e3b0c44298fc1c149afbf4c8996fb92427ae41e464… │
│ Certificate ID:                 d5a371c1-90a2-4a0b-93fa-d8d4791e8432        │
│ Cipher Cascade:                 AES-256-GCM + ChaCha20-Poly1305 Cascade     │
│ Ephemeral Entropy:              512 bits (OS CSPRNG)                        │
│ RAM Key Zeroization:            VERIFIED (Purged via ctypes.memset 0x00)    │
│ Physical Disk Sectors:          OVERWRITTEN (3-Pass DoD + fsync)            │
│ Decryption Possibility:         0.00000000000000000000% (2^-512)            │
│ Black Hole Container:           classified_report.pdf.lwl                   │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 2. Попытка расшифровки (`decrypt`)

Любая попытка расшифровать контейнер подтверждает его безвозвратный статус и выводит сертификат уничтожения:

```bash
lastword-lock decrypt classified_report.pdf.lwl
```

Вывод:
```
┌─────────────── ❌ IRREVOCABLY ENCRYPTED (DIGITAL BLACK HOLE) ───────────────┐
│ Target File:             classified_report.pdf                              │
│ Original SHA-256 Proof:  e3b0c44298fc1c149afbf4c8996fb92427ae41e464…       │
│ Certificate ID:          d5a371c1-90a2-4a0b-93fa-d8d4791e8432               │
│ Destruction Date:        2026-10-24T22:30:15.000000+00:00                   │
│ Key State in RAM:        ZEROIZED & DESTROYED (ctypes.memset 0x00)          │
│ Cipher Cascade:          AES-256-GCM + ChaCha20-Poly1305 Cascade            │

Decryption Error: This container was permanently crypto-shredded.
All keys were overwritten in volatile RAM with zeroes upon generation.
There are no keys in existence to decrypt this file.
```

### 3. Инспекция контейнера (`inspect`)

Отображает полный криптографический паспорт контейнера и подтверждение затирания ключей:

```bash
lastword-lock inspect classified_report.pdf.lwl
```

### 4. Тестирование пропускной способности (`benchmark`)

Замеряет реальную скорость генерации 512-битной энтропии, каскадного шифрования ChaCha20+AES и очистки памяти:

```bash
lastword-lock benchmark
```
*(Скорость на современном процессоре достигает ~700–800 МБ/с).*

### 5. Локальный веб-сервер с QR-кодом для смартфонов (`server`)

Запускает веб-приложение в локальной сети и генерирует QR-код для моментального открытия на iPhone / Android:

```bash
lastword server
```
Наведите камеру смартфона на QR-код в консоли — страница откроется в Safari или Chrome. Все вычисления и зануление памяти происходят **локально на процессоре телефона через WebCrypto API**.

---

### 6. Автономный изолированный HTML-файл (`export-html`)

Создаёт единый самодостаточный файл `.html` (со встроенными стилями и скриптами), который можно передать на любое устройство (флешка, AirDrop, Telegram, Email) и использовать **без интернета и без установки Python**:

```bash
lastword export-html -o offline_shredder.html
```

## 🔒 Математическая гарантия

- **Энтропия ключей**: $2^{512}$ вариантов. Чтобы перебрать такое количество ключей, всей энергии звёзд в наблюдаемой Вселенной не хватит даже для проверки ничтожной доли процента комбинаций.
- **Очистка памяти**: Использование Си-вызова `ctypes.memset` гарантирует, что ключ не останется в неиспользуемых фрагментах оперативной памяти.
- **Аутентичность заголовка (AES-GCM AAD)**: Заголовок контейнера связан с шифротекстом. Подделать сертификат или метаданные невозможно.
